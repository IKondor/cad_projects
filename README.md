# CAD-проекты

Монорепо параметрических CAD-моделей на [CadQuery](https://cadquery.readthedocs.io/)
(Python-обёртка над ядром OpenCascade — тем же, что под FreeCAD и рядом
промышленных CAD). Модель — это исходный код: она версионируется, диффится
и правится по параметрам, а не перетаскиванием мышью.

## Требования

Только [`uv`](https://docs.astral.sh/uv/) — он сам поставит нужную версию Python
и все зависимости. Аналог `nvm` + `corepack` + `npm workspaces` в одном флаконе.

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh   # если ещё не стоит
```

Системный Python **не используется**: версия запиннена в `.python-version`
(сейчас 3.12 — свежее CadQuery пока не поддерживает), зависимости живут
в локальном `.venv/`, точные версии зафиксированы в `uv.lock`.

## Быстрый старт

```bash
uv sync --all-packages                      # создать окружение
uv run python projects/starter-cube/model.py
```

Модели выгружаются в `out/` рядом со скриптом (в git не попадают — это
артефакты сборки, воспроизводимые из кода).

## Структура

```
packages/           переиспользуемый код
  cadkit/             экспорт, просмотр — общее для всех проектов
projects/           сами проекты, по папке на изделие
  starter-cube/       шаблон: куб 2×2×2 м
```

Проект — это папка с одним или несколькими `.py` и любыми файлами рядом:
текстовое ТЗ, фото помещения, референсы, заметки. Всё, кроме `out/`,
коммитится вместе с моделью.

## Как завести новый проект

```bash
cp -r projects/starter-cube projects/имя-проекта
rm -rf projects/имя-проекта/out
```

Поправить `name` в его `pyproject.toml` и выполнить `uv sync --all-packages` —
workspace подхватывает новую папку автоматически (см. `members` в корневом
`pyproject.toml`). Зависимости, нужные только этому проекту, добавляются
локально:

```bash
uv add --package имя-проекта имя-пакета
```

## Соглашения

**Все размеры в миллиметрах.** CadQuery безразмерный, поэтому единица держится
договорённостью: `2000` — это 2 метра. Мебельное производство работает в мм,
так что расхождений с деталировкой не возникает.

**Параметры — сверху отдельным блоком**, построение — в функции `build()`,
запуск — под `if __name__ == "__main__"`. Тогда модель можно и запустить
напрямую, и импортировать из соседнего скрипта (например, чтобы посчитать
спецификацию или прочность по той же геометрии).

## Просмотр модели

3D-вьюер — расширение VSCode **OCP CAD Viewer** (`bernhard-42.ocp-cad-viewer`,
предлагается к установке автоматически).

Порядок такой: вьюер — это **приёмник**, он открывается пустым и ждёт модель.
Чтобы что-то увидеть, надо запустить скрипт — `show()` отправит модель
в уже открытое окно.

```bash
uv run python projects/starter-cube/model.py
```

Если вьюер не запущен, `show()` молча пропускается — скрипты остаются
работоспособными из консоли и в CI.

### ⚠️ Не пользуйся Library Manager расширения

В панели расширения есть кнопки установки библиотек (Quickstart / Install
для `cadquery`, `build123d` и прочего). **Их нажимать нельзя.** Они делают
`pip install` напрямую в `.venv` мимо `uv`, и лок-файл перестаёт описывать
реальное окружение.

Конкретно quickstart для `build123d` ставит сборку `cadquery-ocp-novtk` —
вариант OCP, собранный без VTK. Она пишет в тот же каталог `site-packages/OCP/`,
что и обычная `cadquery-ocp`, затирает её файлы, и CadQuery перестаёт
импортироваться с невнятной ошибкой `ImportError: cannot import name
'IVtkOCC_Shape'`.

Если это всё же случилось — лечится восстановлением окружения из лока:

```bash
uv sync --all-packages --reinstall-package cadquery-ocp --reinstall-package cadquery-ocp-proxy
```

Все зависимости ставятся только через `uv add`.

## Форматы экспорта

| Формат | Для чего |
|---|---|
| **STEP** | Основной обмен: точная геометрия, понимают все CAD. Это отдают исполнителю. |
| **STL** | Триангулированный меш: рендер в Blender, 3D-печать. Точность теряется. |

Для раскроя на ЧПУ обычно нужен ещё DXF плоских деталей — добавим в `cadkit`,
когда дойдёт до реального изделия.
